## `MyTools.tab/Testing.panel/infopane.pulldown/PrintCurrentPDF.pushbutton/script.py`

- **Intended behaviour:** printer-specific configuration; submit each view with an identifiable output; do not open a PDF until its destination exists. A viewer-launch failure is distinct from a print/generation failure.
- **Special constraints:** temporary Revit model content and print setup used to control output must be cleaned up appropriately. Explicitly configure each submitted view to avoid print-setting leakage.
- **Source:** prints the active view through `lib/pdfprinting.py`; sanitizes its sheet number/name, prefixes the current date and opens the resulting PDF after printing returns. Printer-specific work is delegated to `lib/pdf24printing.py`, with output and setup helpers in `lib/pdfprintfiles.py` and `lib/revitpdfsettings.py`.
- **Reference:** [PDF24 and Revit printing](docs/pdf24.md).
- **Verification status:** the historical reference reports a Revit 2026 print-setup persistence issue without identifying the original command. The current command's path and helper imports were inspected; an end-to-end print test was not performed during documentation consolidation.

## `MyTools.tab/Working.panel/General.pulldown/GeometryJoin.pushbutton/material_order_ui.py`

- **Entry point:** `GeometryJoin.pushbutton/script.py` calls `show_material_order` before joining selected elements.
- **Intended behaviour:** save names rather than document-specific IDs; preserve missing names in presets; append newly discovered materials after existing priorities. An initial alphabetical setup must not be flagged as an imported/remembered-order change.
- **Execution:** Close/X may save preferences but must not modify the Revit model; only explicit Run initiates the command after the dialog closes.
- **Reference:** [WPF dialogs and preferences](docs/wpf.md).
- **Verification status:** source confirms the universal settings file, preset reconciliation, close/save handling and Run result. No end-to-end UI test was performed during documentation consolidation.

## `MyTools.tab/Working.panel/QRCode.pushbutton/script.py`

- **Dependencies:** CPython (`#!python3`), Segno 1.6.6 bundled in `lib/segno` with its upstream LICENSE, and the existing PyPNG `lib/png.py`. No qrcode/Pillow imports. Segno wheel SHA256: `28c7d081ed0cf935e0411293a465efd4d500704072cdb039778a2ab8736190c7`.
- **Behaviour:** automatic standard QR version, error correction M without boosting, and 10-pixel module cells with centred 8-pixel coloured squares. A 20-pixel white border surrounds each side (`QUIET_ZONE = 2` at `BOX_SIZE = 10`); the one-pixel inset within each module cell remains. Split each matrix axis at the nearest whole module to one-third and two-thirds, excluding any outer border. Each of the nine regions is approximately one-ninth of the matrix area; segment widths/heights differ by at most one module. Choose one colour per dark module before drawing its pixels, so a square cannot straddle two colours. Keeps the existing 3-by-3 colour arrangement (including repeated colours), RGB values, input dialog and `~/Downloads/qrcode_color_replaced.png` destination. Segno may select a different encoding/mask from qrcode; gaps apply to all dark modules, including finder patterns. Generation/write errors propagate; cancellation skips generation. No Revit transactions or model edits.
- **Compatibility:** explicitly initializes the .NET Form base before setting WinForms properties; see `docs/ironpython.md`.
- **20-pixel border (2026-10-29):** requested after the H-shaped-code investigation; only `QUIET_ZONE` changed from 0 to 2. This is two modules per side, rather than the standard four-module quiet zone discussed with the user. Real URL and Unicode generation/PNG round trips passed using the installed pyRevit CPython 3.12.3 executable outside Revit: all four outer 20-pixel bands were white, each dimension increased by 40 pixels, and the cropped interior was byte-for-byte identical to the former borderless raster. Both samples produced 290-by-290 PNGs. No H-shaped cutouts were implemented. Prior borderless and 40-pixel-border measurements below describe earlier versions; modal interaction and scanner decoding were not repeated for this constant change.
- **QR input UI (2026-10-28, updated 2026-10-29):** `qr_input_ui.py` and `QrInput.xaml` replace the original WinForms input with a GeometryJoin-style WPF dialog for the web address/text being encoded. Local `Styles.xaml` and light/dark palettes derive the text/button styling and palette values from GeometryJoin without changing that command or importing its material-order logic. The dialog follows Revit's current theme and applies the matching native title-bar colours. It shows the existing Downloads output path, returns input verbatim only on Generate, disables Generate for blank/whitespace-only input, and returns `None` on Cancel/X. Normal click runs the tool; the temporary Shift-click preview, `config.py`, and preview-only code were removed at the user's request. The native Explorer result dialog remains the post-save step.
